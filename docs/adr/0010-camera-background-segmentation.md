# ADR 0010: Camera background effects with a converted MediaPipe model on tract

Status: accepted (2026-10-20)

## Context
Issue #85 asks for free camera background blur and bundled preset backgrounds (no custom uploads, which are paid, and no Discord artwork). Both need a person mask. The budget rules stay: idle RAM below 150 MB, no work when the feature is off, no FFmpeg, nothing slow on the UI thread or in audio callbacks, byte-bounded buffers, and only appropriately licensed assets.

## Decision
- **Model:** Google's MediaPipe selfie segmenter (256x256 input, one person-probability channel, 249,537 bytes, Apache-2.0 per its model card), downloaded from the official `storage.googleapis.com/mediapipe-models` URL and pinned by SHA-256 in `crates/fastcord-video/native/selfie/selfie-model.json`. It is small enough to run on the CPU everywhere, needs no GPU API, and its licence permits redistribution with notice (`docs/THIRD_PARTY_NOTICES.md`).
- **Runtime:** `tract-onnx` 0.19.16, which `deep_filter` (DeepFilterNet, ADR 0004) already links. `Cargo.lock` gains no crate, only an edge from `fastcord-video`; the release binary grows by the embedded files (about 0.8 MB) and whatever extra code this crate pulls from tract. tract does not read TFLite, so `convert_selfie_segmenter.py` translates the model once, offline, operator by operator (11 operator kinds; float16 weights widened; NHWC to NCHW). The ONNX file is committed with the original, the converter and both hashes. Agreement with the original was checked in TensorFlow Lite on structured inputs (4e-5 maximum difference) and is pinned by a Rust test with reference values from TensorFlow Lite.
- **Rejected:** ONNX Runtime or a GPU path (a large native dependency and a second inference stack for a 250 KB model); OpenCV (large, C++); writing a TFLite interpreter (more code to own than a 150-line converter); a non-neural background subtraction (it cannot separate a still person from a still room); models of unclear licence or provenance (several popular matting models are GPL or non-commercial).
- **Placement:** a stage on the capture thread between capture and encoder (`fastcord-video::effect`). Only inference runs elsewhere: one dedicated worker, handed at most one reduced 256x256 picture at a time (no queue), at most about 15 a second, returning a temporally smoothed 256x256 mask. The capture thread keeps the newest mask and composites every full-rate picture, so frame pacing never waits for the model. The preview and the encoder both receive the composited picture. The preview mirror is applied afterwards, to the preview only.
- **Lifetime:** with the effect off there is no worker, no model and no copy. Choosing an effect starts the worker (it parses and optimizes the model itself, so a slow load never stalls the camera); choosing Off, stopping the camera or ending the call joins the thread and frees the model.
- **Fail closed:** until the first mask exists the whole picture is background (blurred or the preset), and if the model cannot load or run the camera is turned off with an explanation; the unprotected picture is never sent in its place.
- **Presets:** four pictures generated by `assets/camera/generate_presets.py` from formulas (gradients, soft light spots, a stripe pattern): original work, no third-party artwork, stored as 320x180 NV12 and enlarged bilinearly.

## Consequences
- Measured on a Ryzen 7 7700 (release): inference 27.7 ms per mask (tract, single thread), blur plus composite about 4 ms per 1280x720 picture, 46 % of one core with the effect on at 30 fps (about 5.7 % of the machine). The effect adds 9.6 MB of resident memory (22 MB peak while loading).
- The mask can trail fast movement by about 100 ms; the smoothing and the soft edge hide most of it. Other people in the frame are treated as the person if the model says so.
- The converted model and tract's input layout are fixed; replacing the model means a new conversion, new hashes and a new ADR.
